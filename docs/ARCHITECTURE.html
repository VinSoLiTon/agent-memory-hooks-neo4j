njhook — Architecture & Operations

A hybrid agent-memory system on top of Neo4j. Hooks capture session events from multiple coding agents; a nightly “dream” phase distills them into durable markdown memories; a hybrid recall engine injects the right memories back into future sessions — across Claude Code, Codex, Cursor, and Gemini.

Neo4j property graph Capture → Dream → Recall Local-first (llama.cpp) + hosted fallback Vector + Lucene hybrid recall Lifecycle & audit governance CLI · REST · MCP · Dashboard

This document is a self-contained reference for engineers and agents new to the system. Diagrams render via Mermaid (CDN); every table and flow is grounded in the source modules named in each section. Read §1 for the mental model, then dive into the phase that concerns you.

1 System Overview

njhook closes a three-phase memory loop. Every interaction an agent has is captured as an immutable event; periodically those events are distilled into a small set of durable, typed memories; and at the start of (and during) every later session the most relevant memories are recalled and injected back into the agent’s context.

HARD RULE — never traverse the event chain with a variable-length path MATCH (s)-[:FIRST_EVENT|NEXT*0..]->(e) materializes a path for every reachable event and blows Neo4j’s transaction-memory pool (MemoryPoolOutOfMemoryError, ~2.7 GiB) on any session past ~150 events. Always walk the linked list one NEXT hop at a time (_walk_session_events), with a seen set to guard against corrupted/branching chains. Also: Neo4j cannot MERGE on a null property value — status-only audit ops therefore carry content_snapshot = null and key revisions on ts.

3 Capture Path

Each agent fires hooks on lifecycle events. A thin per-client shell wrapper pipes the hook JSON on stdin to the shared hooks/log_event.py --client <name>. The hot path scrubs secrets, builds the event node, and either writes it straight to Neo4j (direct mode) or appends it to a durable spool for asynchronous ingest.

Spool & DLQ

  • Dir: $HOOKS_SPOOL_DIR (default ~/.njhook/spool).
  • Files: events-YYYY-MM-DD.jsonl (one record/line, fsync on append) + dlq.jsonl.
  • DLQ record: {ts, error, raw} — ts powers a per-hour failure-rate health metric.
  • Metrics: backlog_count(), dlq_rate_per_hour(window).

Ingest worker idempotency

  • Reads every spool file, event_schema.upcast() per record.
  • Malformed JSON / missing event_id → dead-letter, continue.
  • Inbox marker = the event’s existence: if event_id already in the graph, skip — replay never duplicates.
  • A file is deleted only when all its records are ingested/skipped/dead-lettered; a write failure keeps the file for retry.

Event schema & versioning

SCHEMA_VERSION = 2. Old spool records are never rewritten — they are upcast on read through a transformer chain (v1→v2 promoted app_id into the event props). Fields map onto the OpenTelemetry GenAI convention (client→gen_ai.system, model→gen_ai.request.model, tool_name→gen_ai.tool.name, …).

Privacy on the hot path Every user-content field (prompt, tool_input, tool_response, last_assistant_message, transcript) is run through privacy.scrub() before storage. Directories listed in the opt-out file are never logged; high-sensitivity directories tag events sensitivity='high', which later blocks remote egress in the dream phase unless DREAM_ALLOW_SENSITIVE_EGRESS=1.

4 Dream Phase — nightly distillation

The dream phase reads sessions with new events, asks an LLM to distill them into markdown memories, runs every candidate through a stack of admission gates, then writes the survivors — recording provenance, token cost, and an immutable revision for any changed body.

Admission gates in detail

GateFires whenNEW memory →UPDATE to active →Failure mode
Grounding (A-MAC)overlap(body, transcript) < 0.10pending_reviewexempt (stays active)empty transcript ⇒ score 1.0 (don’t gate)
Critique (#18)opt-in; LLM says body not faithful to transcriptpending_reviewexemptTrue-on-error — lenient; only an explicit “no” quarantines
Anti-poison (H3)directive wording AND events < 5 AND novelty ≥ 0.6pending_reviewheld — prior body kept, incoming saved as update_held revisionno events ⇒ skip (can’t assess provenance)
Contradiction (E)opt-in; judge says NEW contradicts an active memorypending_review + :CONTRADICTSexisting stays activeFalse-on-error — conservative; can only miss, never wrongly flag
Two opposite failure stances, on purpose The contradiction judge returns False on any error (never wrongly quarantine a good memory by falsely claiming a conflict). The faithfulness critic returns True on any error (never quarantine a good memory by a flaky verdict). Both stances protect a good memory from a misbehaving model — they just sit on opposite sides of the same boolean.

Anti-poisoning signals

  • Directive — body contains an imperative marker (always, never, must, do not, delete, drop, disable, sudo, rm -, the command is, …).
  • Thin — fewer than DREAM_POISON_MIN_EVENTS (5) events backing it.
  • Novel — novelty_score = 1 − overlap(body, same-prefix corpus) ≥ DREAM_POISON_NOVELTY_MIN (0.6).

The poisoning vector is “one short session injecting a durable, unverifiable rule.” Updates are held (not pending_review) because routing an update to pending would still clobber the trusted body via the unconditional SET m.content — instead the established body stays active and the rejected incoming body is preserved as a revision for audit/recovery.

Watermark, ordering & backlog

Watermark & transient back-off

:Session.last_dreamed_at advances on a clean run — even a genuine 0-yield — so low-signal sessions aren’t re-dreamed forever. But a 0-yield caused by a provider error (local model busy / unreachable / timeout) is deferred: the watermark is left in place and the next run retries it (no fallback egress on a blip). Critical in full-offline mode — surfaced as the defer column in njhook dream-stats.

Backlog guard (item #24)

_order_targets sorts (never-dreamed, watermark asc, session_key) — a stable oldest-first order. --max-sessions N processes N qualifying sessions then stops, logging that the rest drain next run. The watermark acts as the resume cursor.

λ = ln(2) / (half_life_days × 24) per hour. Identity/tooling facts decay slowly; project notes fast.

Lifecycle filter & time travel

  • Active-only: every retrieval path enforces coalesce(status,'active')='active' AND NOT archived. Pending / rejected / superseded never inject.
  • As-of (recall --as-of <ISO>): swaps the live filter for a bi-temporal window valid_from ≤ T < valid_until and reconstructs each body from the :MemoryRevision chain — “what did memory look like on date T?”.
  • Worklists: never_injected (active, access_count=0, older than 30d — dead weight) and effectively_dead (used once but recency below 0.05 floor — decayed out). Surfaced by njhook stale.

Injection format & budget

SessionStart injects three buckets — Profile, Tools, Project (name) — each memory rendered as ### path + body, value-density-ordered, truncated at CHAR_BUDGET = 4000 with an explicit cut notice and a _memory used: …_ citation footer. After injection, access_count/last_accessed_at are bumped for every emitted path (which feeds the recency/usage signals next time).

6 Review, Lifecycle & Governance

Every memory is in exactly one lifecycle state. Recall serves only active; the other three are advisory or historical. Transitions come from humans (njhook review / dashboard), the nightly’s detectors, or automatic conflict resolution.

Conflict resolution — authority × recency

When two memories contradict, auto_resolve picks the winner by source authority first, then recency. Detection draws candidates from the vector channel (cosine > 0.85) ∪ the fulltext channel (catches antonym-style conflicts that score low on cosine), and an LLM judge confirms. The nightly uses the asymmetric flag_new_contradiction — only the NEW memory is quarantined; the established one keeps serving recall.

Audit log

Every mutation appends an immutable :MemoryRevision via VERSION_OF. Content ops (dream_create, dream_update, edit) snapshot the prior body; status-only ops (approve, reject, supersede, flag_contradiction, quarantine) carry content_snapshot = null — the prior status is the load-bearing datum, so the body isn’t re-copied (item #23). njhook audit <path> reconstructs one memory’s timeline; --recent gives a graph-wide view.

Backup, restore & rehearsal

A versioned JSON backup carries memories, revision chains, supersessions, and full session/event chains. restore is an idempotent upsert (by path / session_key) with pre-flight shape validation. rehearse-restore (Phase H4) seeds a disposable marker, runs a real backup→restore round-trip, verifies content + lineage, and records a :RehearsalRun — the health check warns if the last rehearsal is stale or failed.

A Glossary & Hard Rules

Glossary

TermMeaning
DreamThe periodic distillation phase that turns raw events into durable memories.
RecallRetrieval + ranking + injection of relevant memories into a new session.
GroundingToken overlap between a candidate memory and its source transcript — the anti-fabrication signal.
CritiqueOpt-in LLM faithfulness check; catches fluent hallucinations grounding can’t (value inversions).
PoisoningA short adversarial session injecting a durable, unverifiable directive.
Watermarklast_dreamed_at — the resume cursor that keeps the dream incremental.
RRFReciprocal Rank Fusion — combines the vector and lexical rank lists (K=60).
kindThe 15-type semantic label on a memory (the path prefix is the orthogonal storage axis).
session_keyclient:session_id — the composite identity that prevents cross-client collisions.
as-ofBi-temporal query: reconstruct the active memory set as it stood at an arbitrary timestamp.

Hard rules to internalize

  1. Never walk the event chain with [:FIRST_EVENT|NEXT*0..] — it OOMs Neo4j. Hop one NEXT at a time with a seen guard.
  2. Neo4j cannot MERGE on a null property — status-only revisions key on ts and store content_snapshot=null.
  3. Gates only downgrade a NEW memory; an update to an existing active memory is never silently hidden (it’s held, not pended).
  4. Recall injects active only — pending/rejected/superseded are invisible to agents.
  5. Local-first by default; high-sensitivity content never egresses to hosted models unless explicitly allowed.
  6. Nothing is hard-deleted on the write path — supersede + revision chain preserve lineage.
